# 红队知识库检索

## 何时使用

当用户需要下面这些能力时使用本 skill：
- 查询某个攻击技术是否已有实现
- 查找某个项目、函数、字符串、IOC 或配置是否真实出现
- 从知识库中定位与当前任务最相关的代码或文章证据
- 对多个项目做横向比对，提炼共性实现方式

## 核心约束

1. 这是关键词检索，不是语义检索。
2. 先粗筛，再精读，不要一上来就堆大量接口调用。
3. 回答必须给出证据来源，不能只给结论。
4. 若查询包含中文，必须使用 `curl -s --get --data-urlencode "q=..."`。
5. 若 `{{REDTEAM_KB_BASE_URL}}` 未配置，直接说明缺少服务地址，不要伪造知识库结果。

## 常用接口

- 搜索：`{{REDTEAM_KB_BASE_URL}}/rtkb/api/search`
- 软件列表：`{{REDTEAM_KB_BASE_URL}}/rtkb/api/software`
- 文章列表：`{{REDTEAM_KB_BASE_URL}}/rtkb/api/articles`

如果用户已经给出明确项目名、函数名、路径、字符串或 IOC，优先做精确检索，不要先做宽泛搜索。

## 工作流

1. 明确检索目标。
   - 提取项目名、函数名、字符串、IOC、攻击技术名或主题关键词。
   - 代码相关问题优先用英文关键词，文章相关问题可用中文短术语。

2. 先做粗筛。
   - 用 `/search` 或 `/software/search` 找候选项目、文件和文章。
   - 控制返回量，优先看最相关的前几项。

3. 再做精确确认。
   - 命中某个项目后，继续使用 `detail`、`tree`、`file`、`grep` 收缩范围。
   - 对明确的字符串、函数、路径，优先 grep 或局部文件读取。

4. 组织证据。
   - 说明命中了什么。
   - 说明它为什么相关。
   - 给出后续建议继续看哪些文件、函数或文章段落。

## 查询建议

- 代码检索优先用英文关键词或标识符。
- 中文检索建议使用 2-4 字术语。
- 不要把自然语言长句直接当查询词。
- 如果第一次召回不佳，马上换一组更短、更具体的词。

## 输出格式

```text
检索结论
- 结论:
- 为什么相关:

证据
- 项目 / 文章:
- 命中文件或段落:
- 关键片段说明:

下一步建议
- 建议 1:
- 建议 2:
```

## 护栏

- 不要把搜索结果列表原样堆给用户。
- 不要因为只命中 README 或介绍文字，就把功能当成已证实。
- 若证据不足，明确说“只找到候选，还需继续确认”。
