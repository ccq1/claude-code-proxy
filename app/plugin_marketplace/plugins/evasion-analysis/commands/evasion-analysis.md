使用 `evasion-analysis` skill 协助当前任务。

执行原则：
1. 先扫描当前工作目录，优先寻找样本、反汇编摘录、字符串输出、API 日志、沙箱报告和调试笔记。
2. 若只有一个明显输入，直接开始分析，不要先要求用户手动传参。
3. 若有多个候选文件，优先采用最接近用户问题、内容最完整的输入，并在回答里说明你基于哪些相对路径做了判断。
4. 引用证据时优先使用相对路径。
5. 把环境探测、反调试、延时执行和载荷解锁逻辑分开分析。
6. 标明每个检查是硬阻断、软信号，还是单纯降噪手段。
7. 先解释这些逻辑如何影响真实投放与沙箱判定，再给绕过思路。
8. 输出要能直接服务于样本复现、沙箱改造和分析环境补强。
9. 对大型沙箱报告、API trace 或字符串转储，先用 `rg -n` 定位关键 API、注册表项、厂商字符串和睡眠逻辑，再只读取周边片段。
